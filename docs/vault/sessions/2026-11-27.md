# 2026-11-27 – sửa gấp màn đen khi không có TeamViewer (nhánh `claude/urgent-virtual-display`)

## Mục tiêu
Màn laptop hỏng; không mở TeamViewer thì RemoteView chỉ thấy đen vì nó *phản chiếu* output có sẵn, không tự tạo màn hình. Dựa trên báo cáo Gemini "Giải Pháp Kiến Trúc RemoteView" (mục 2.1, 3.2).

## Thay đổi
- `crates/host-win/src/sudovda.rs` (mới): client IOCTL SudoVDA (mã lấy từ `sudovda-ioctl.h` thật, không phải mã minh hoạ trong báo cáo Gemini), ping watchdog, gỡ khi Drop, tìm `\\.\DISPLAYn` qua QueryDisplayConfig, `make_primary`, `install()` (certutil + SetupAPI).
- `engine.rs`: `--display virtual`; extend/virtual/mirror-không-có-output → tạo màn ảo theo `--width/--height` (mặc định 2800×1752@120).
- `apps/win-ui`: lựa chọn "Màn hình ảo chính", trạng thái + nút cài driver, tự cài (UAC) trước khi chia sẻ, chế độ `--install-vdd`.
- CI: tải driver đã ký từ release Apollo, nhúng bằng `embed-vdd`.
- Xem [[decisions/ADR-0003-sudovda-virtual-display]].

## Ghi chú từ Gemini (chưa làm, cần kiểm chứng)
- Thanh trượt chất lượng/FPS/độ phân giải bị bỏ qua ở chế độ USB; hộp 64dp góc phải nuốt nút đóng; thiếu `--iid 0` khi cài WinUSB; Shutdown cắt upload log Android sau 8 KiB; cấp phát lại staging texture 8,3 MB mỗi khung; ghi USB bulk đồng bộ trên luồng chính.
- "Con trỏ lệch do DPI": host đã gọi PER_MONITOR_AWARE_V2 (`session_state::set_dpi_aware`) → cần log thật để xác nhận.

## Cập nhật: xem/điều khiển màn hình khóa (dịch vụ SYSTEM)
- Mục tiêu: như TeamViewer, vẫn thấy và điều khiển laptop khi Windows khóa (Winlogon / UAC). Xem [[decisions/ADR-0004-system-service-lock-screen]].
- `RemoteView.exe --service` (`RemoteViewSvc`, `apps/win-ui/src/service.rs`): pipe `\\.\pipe\RemoteViewSvc`, chạy chính exe với `--host-worker` bằng token SYSTEM trong phiên console, chuyển tiếp JSON lines. Cài cùng SudoVDA bằng `--install-all <dir|->` (một UAC); `--uninstall-service`.
- `host.rs`: ưu tiên pipe dịch vụ, không có thì tiến trình con như cũ (`Link`/`LinkEnd`).
- `session_state::follow_input_desktop/running_as_system/DesktopFollower`: capture, cursor, input, monitor gắn vào desktop nhập liệu khi chạy SYSTEM; cờ `locked` không chặn nữa ở chế độ này.
- `service_proto.rs`: allow-list tham số, parse dòng spawn, bơm pipe (có test).
- TODO: thử thật trên Windows (khóa máy → thấy màn hình đăng nhập, gõ mật khẩu từ máy bảng); kiểm tra cảm ứng/bút vào Winlogon; hạn chế pipe theo SID user nếu cần chặt hơn.

## Cập nhật (Gemini multi-agent P1 + P2 sprint — nhánh `claude/urgent-virtual-display`)
- **Mục tiêu:** Hoàn thiện toàn bộ backlog P1 + P2 còn lại sau bàn giao #2 (`78eaf87`), xem [[decisions/ADR-0005-native-amf-and-telemetry]].
- **Encoder hiệu năng cao (`crates/host-win/src/encode/`):**
  - Thêm bộ mã hóa **AMD AMF DX11 gốc** (`amf_ffi.rs`, `amf.rs`, nạp `amfrt64.dll` từ System32, không cần SDK/clang, HEVC/H.264 `ULTRA_LOW_LATENCY`, `QueryTimeout = 50ms`, vòng 4 texture NV12 qua VideoProcessor + dự phòng BGRA). Chuỗi ưu tiên mới: `AmfHevc -> AmfH264 -> MfHevcHw D3D -> MfH264Hw D3D -> MfHevcHw SysMem -> MfH264Hw SysMem -> OpenH264 đa slice`.
  - Thay `openh264` bậc cao bằng `openh264_mt.rs` (`openh264-sys2` `SM_FIXEDSLCNUM_SLICE`, `iMultipleThreadIdc = 2..8`, tắt toàn bộ cảnh báo `ParamValidation`, đổi bitrate trực tiếp).
- **Giao thức, đo độ trễ thực & gom log một chạm (`crates/proto`, `crates/session`, `crates/android-core`, `apps/android`, `apps/win-ui`):**
  - Thêm `Ping` (`0x0F`), `Pong` (`0x10`, host tự đáp), `RequestLog` (`0x11` → Android `STATE_LOG_REQUEST = 12`).
  - Android `LowLatencyDecoder` đo `decodeUs` thực (`queueInputBuffer -> onOutputBufferAvailable`) + `codecThreadTid` cho ADPF; `rv-android-core` gửi `FeedbackStats` 1s/lần (RTT, loss, kbps, `decode_us`) và xả batch `rx`; HUD Android hiển thị `RTT · Dec · Mbps`; Windows GUI ghi log `stats` định kỳ, hiện `decode_ms`, hỗ trợ `set_resolution 0x0` (reset về theo thiết bị), và bấm **Xuất log** tự gửi `request_log` kéo log Android gộp vào file zip.
  - Bật điều khiển chất lượng/FPS trực tiếp trong phiên (`nativeSetStreamQuality`/`nativeSetBitrate`/`nativeSetMaxFps`) và tôn trọng cài đặt TouchMode/FPS/Scale ở chế độ USB.
- **LAN end-to-end & Điều khiển:**

  - Hiện thực **Ctrl+Alt+Del (`SendSAS(FALSE)` từ `sas.dll`)** trong `input_win.rs` + bật `SoftwareSASGeneration = 1` khi cài dịch vụ; bỏ cảnh báo giả serial phần cứng AOA (`aoa.rs`).
- **UX & Bảo mật Windows / Android / CI:**
  - Windows (`apps/win-ui`): `build.rs` nhúng `.ico` đa kích thước + manifest `PerMonitorV2` (không thêm crate), khay hệ thống thật (`tray.rs`), Job Object (`job.rs`), `driver.rs` giải nén `wdi-simple.exe` vào `%LOCALAPPDATA%` + `TerminateProcess` khi timeout, `update.rs` tải vào thư mục app + xác minh SHA-256 + dừng host trước khi thay exe + dọn `RemoteView.old.exe` lặp lại, `service.rs` phát hiện lệch đường dẫn `binPath`.

## Cập nhật (Tối ưu FPS 120 Hz & sửa xuất log Windows sau test máy thật `cf7ce8e`)
- Xem chi tiết phân tích nguyên nhân gốc tại [[bugs/2026-11-27-low-fps-timer-sw-decoder]].
- **Host Windows (`crates/host-win`):**
  - `engine.rs`: bật `timeBeginPeriod(1)` (RAII `HighResTimerGuard`) + `THREAD_PRIORITY_HIGHEST` cho `video_thread` và `run_session`; tách nhận `io.try_recv()` khỏi chờ khung hình (`vrx.recv_timeout(1ms)` khi rảnh) để cắt trễ 15.6 ms; sửa pacing 120 Hz tránh chia đôi xuống 60 FPS; tách `VideoEvent::Bitrate` (chỉ gửi `StreamConfig`, không spam `DisplayConfigChange`); snap `fit_size(2800x1752, 2560x1600) -> 2560x1600`; tăng `sync_channel(4)`.
  - `encode/{amf_ffi.rs,amf.rs,mf.rs}`: fallback `LOAD_LIBRARY_SEARCH_DEFAULT_DIRS` + `GetLastError`; poll `QueryOutput` trên `AMF_REPEAT` (tránh `HwSupervisor` loại nhầm AMF); fallback `LOW_LATENCY`; đặt `CODECAPI_AVEncCommonQualityVsSpeed = 0` và áp lại sau `SetInputType` trên MF.
  - `sudovda.rs` & `capture_win.rs`: ép đúng chế độ `WxH@Hz` (120 Hz) bằng `ChangeDisplaySettingsExW` sau khi tạo màn hình ảo và log `@Hz` thực tế.
  - `frame_stats.rs`: loại khoảng nghỉ tĩnh `> 500 ms` khỏi mean/var/1% low (đồng bộ với Android).
  - `logfile.rs`: sửa `is_log_of` không cho `remoteview-service-*.log` đẩy log GUI `remoteview-<timestamp>.log` ra khỏi file ZIP xuất log.
- **WinUI (`apps/win-ui/src/app.rs`):** thêm `QualityDebounce` (150 ms + flush khi thả kéo) chống spam 50 lệnh `SetQuality`/2s khi kéo thanh trượt.
- **Android (`apps/android`):** sửa `FramePresenter.kt` bỏ spam 360 message/giây lên main thread (idle watcher tự hẹn giờ 3s), `DisplayLock.kt` giữ nhịp cao (để LTPO/PSR phần cứng tự lo thay vì app hạ nhịp), gỡ `ThermalGovernor` tự bóp bitrate 70% / hạ 60 FPS (để HĐH/SoC tự quản lý nhiệt), đặt mặc định `directPresent = true`, `LowLatencyDecoder.kt` chờ 80 ms thử lại bậc `PLAIN` của codec phần cứng trước khi chịu rơi về CPU phần mềm + ghi cảnh báo rõ vào `RvLog`, `DatagramLink.kt` mở thread đọc sau `onOpen()` + rate-limit cảnh báo `handle=0`, `SettingsScreen.kt` cảnh báo rõ khi tắt giải mã phần cứng.
- **Host Windows (`engine.rs`):** lùi `vrx.recv_timeout` từ `1 ms` → `4 ms` khi màn hình đứng yên > 50 ms (giảm 4× số lần đánh thức CPU khi tĩnh, vẫn đánh thức tức thì 0 ms ngay khi có khung hình mới).
- **Chưa kiểm chứng trên máy thật:** tốc độ thực tế của `amf-hevc-hw` / `mf-hevc-hw` và FPS 120 Hz sau khi bật `timeBeginPeriod(1)` + ép 120 Hz SudoVDA + `directPresent = true` trên Vivobook S14 + Tab S10+; nguyên nhân cụ thể nếu `c2.mtk.hevc.decoder.lowlatency` còn rơi về `c2.android.hevc.decoder` (giờ đã có retry 80 ms + ghi log đầy đủ vào `RvLog`).
